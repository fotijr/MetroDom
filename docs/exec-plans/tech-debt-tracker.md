The live status panel and interactive port picker have only been checked by unit render tests, not watched during real playback |

| TD-20 | L | `metrodom play` | Tap/nudge keys are read in the status view and covered only by unit tests of `TapTempo` and `SetSpeed`, not by driving a terminal. `--clock-in` follows tempo, not phase (can drift by up to its 0.5 BPM threshold) and ignores Start/Stop/Continue and Song Position. `--tap` and `--clock-in` are `play` only, one input at a time. Tempo changes rescale the file's tempo map (a file tempo change mid-song still applies, multiplied) |
| TD-21 | M | `src/MetroDom.Core/Arranging/Arranger.cs` | First cut: greedy "most playable notes" pairing, one part per instrument, no way to pin a part to an instrument (parts have roles and seats remove them, but nothing pins a part to an instrument by role). Role detection is name keywords and GM program only, English names, no "percussion" vs "drums" split for pitched percussion tracks off channel 10. Ignores `polyphony` from the profile. Drum notes the kit lacks (e.g. hi-hat 42) are dropped, not substituted. Instrument notes come from the command line; `profile.json` files aren't loaded yet |
| TD-22 | M | `src/MetroDom.Core/Safety/SafetyGovernor.cs` | No duty-cycle or polyphony limit yet (profile `safety` / `polyphony` not loaded). Min interval only applies when the instrument's profile sets it (no CLI flag) |
| TD-23 | M | `src/MetroDom.Conductor/Midi/Identifier.cs` | Discovery is steps 1-3 and on request (`devices --identify`): no identify on hot-plug, `play`/`route` fetch profiles only at start and only for named `-o` ports, no remembered assignments or auto-adding (step 4), no MIDI 2.0 / network discovery. Pairs input and output by identical name, which fits USB-MIDI and CoreMIDI but is unverified on ALSA and Windows. ALSA virtual ports are now duplex for the reply, never run (TD-19). MetroDom's family code and profile SysEx are drafts. A MetroDom device without the profile request costs a full 250 ms wait |
| TD-17 | L | `src/MetroDom.Conductor/Midi/ResilientPorts.cs` | Reconnect matches ports by name, so two identical devices with the same name can't be told apart.
